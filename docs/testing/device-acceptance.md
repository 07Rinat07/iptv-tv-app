# Приёмка на TV Box

## Матрица

- Android 7/API 24, Android 9/10 и Android 12+;
- 2 ГБ и 4 ГБ RAM;
- D-pad, оптическая мышь, тачпад;
- стабильная и ограниченная сеть.

## Обязательные сценарии

1. Запуск → готовый список → импорт → выбор канала → воспроизведение.
2. Сохранённый список → прямой переход в плеер.
3. Сканер → импорт → редактор → плеер.
4. Переключение каналов и полноэкранного режима всеми типами ввода.
5. Media3 → LibVLC fallback на проблемном потоке.
6. Torrent TV `content_id` через встроенный runtime на устройстве без установленного Ace Engine.
7. Повторный запуск того же Torrent TV канала после полной остановки.
8. Серия не менее чем из 20 переключений IPTV ↔ IPTV, IPTV ↔ Torrent TV и Torrent TV ↔ Torrent TV; предыдущая P2P-сессия должна освобождаться.
9. Непрерывная подкачка Torrent TV: retained buffer и входящая скорость продолжают меняться после старта, rebuffer фиксируется числом, а не только визуально.
10. Проверка слышимого звука и выбранной аудиодорожки на каждом запустившемся контрольном канале.
11. Сброс логов → повтор ошибки → экспорт нового журнала.

## Текущий результат

- PASS: один активный Torrent TV канал на чистом эмуляторе API 34 без Ace Stream — 90 секунд, Media3 `READY`, без rebuffer; повторный запуск — 30 секунд.
- FAIL/не завершено: скорость и надёжность переключений, устойчивое пополнение live-буфера на разных swarm, набор недоступных каналов и реальные ARM TV Box.

Это частичный smoke-test, а не итоговая приёмка приложения.

## Длительные тесты

- быстрый этап: не менее 2 часов непрерывного HLS;
- релизный этап: 8 часов, смена канала каждые 3–5 минут;
- критерии: без crash/ANR, память стабилизируется, восстановление не зацикливается, live-буфер продолжает пополняться, предыдущая сессия после переключения закрыта.

## Слабая сеть

- 2–5 Мбит/с;
- 120–250 мс задержки;
- 1–3% потери пакетов.
