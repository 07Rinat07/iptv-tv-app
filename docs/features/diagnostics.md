# Диагностика

Раздел отображает состояние сети, runtime, плеера, Ace Stream и последние журналы приложения.

Для P2P должны различаться этапы `resolve/discovery/handshake/window/startup/ready/stall/stop`, причина завершения и факт пересоздания сессии. Следующий playback-hardening инкремент добавит измеримые retained bytes, скорость получения и потребления, время первого media byte, startup time и rebuffer events. Без этих значений сообщение «подключение» не считается достаточной диагностикой долгого переключения или отсутствующей подкачки.

Каждая запись playback path должна содержать безопасные `playbackRequestId` и `playbackSessionId`. Отменённые новым выбором операции получают статус `superseded/cancelled`; их поздний результат не должен изменять Player UI. Подробный набор событий определён в [`../testing/playback-log-analysis-2026-08-11.md`](../testing/playback-log-analysis-2026-08-11.md).

## Работа с логами

- фильтр по статусу, сообщению и `playlistId`;
- экспорт в Downloads или выбранный документ;
- кнопка «Сбросить старые ошибки» устанавливает новую временную точку журнала;
- записи до этой точки скрываются, а новые ошибки собираются отдельно;
- в базе хранится ограниченная выборка последних событий, поэтому старые записи постепенно вытесняются.

Сброс предназначен для воспроизведения новой проблемы без шума от предыдущих запусков.

При отчёте о проблеме нужно сбросить старые записи, запустить один канал, дождаться результата, переключиться один раз и сразу экспортировать журнал. Идентификаторы, query-параметры, токены и credential-bearing URL в экспорт не попадают.
